8.Biznes qoidalar
1. Buyurtmada kamida bitta mahsulot bo'lishi kerak, mahsulot soni musbat bo'lishi kerak.
2. isAvailable = false yoki o'chirilgan mahsulotni buyurtma qilib bo'lmaydi (aniq xato
xabari bilan).
3. Narxlar hech qachon mijozdan olinmaydi, server o'zi bazadan hisoblaydi (DTO'da narx
maydoni bo'lmaydi). Bu mijoz narxni o'zgartirib yuborishidan himoya qiladi.
4. DELIVERY bo'lsa manzil majburiy. Yetkazib berish narxi sozlamadan olinadi, buyurtma
summasi bepul yetkazib berish chegarasidan oshsa 0 bo'ladi.
5. Minimal buyurtma summasidan kam buyurtma qabul qilinmaydi (sozlamada o'zgaradi).
6. Telefon raqami O'zbekiston formatida tekshiriladi (+998 va 9 raqam).

9.Texnik talablar (professional amaliyotlar)
Arxitektura: Entity / Repository / Service (interface + impl) / Controller / DTO / Mapper
/ Exception qatlamlari, SOLID.
Validation (@Valid) va markazlashgan xato boshqaruvi (@ControllerAdvice),
foydalanuvchiga tushunarli xabarlar, ichki xatolar sirtga chiqmaydi.
Parollar BCrypt bilan, maxfiy ma'lumotlar (DB paroli, Telegram token, JWT kaliti) faqat
environment o'zgaruvchilarida.
CORS faqat o'z frontend domeniga ochiladi.
Rasm yuklash: faqat jpg/png/webp, hajm cheklovi (masalan, 5 MB), fayl nomi tasodifiy
(UUID), rasmlar diskda yoki volume'da saqlanadi, serverdan statik beriladi.
Katta ro'yxatlarda sahifalash (pagination) va tegishli indekslar (slug, category_id,
status, createdAt).
Admin endpoint'lar himoyalangan, ochiq endpoint'lar faqat o'qish va buyurtma yaratish
bilan cheklanadi.
Swagger hujjati to'liq va aniq bo'lishi kerak, chunki Antigravity frontendni shu asosida
yozadi.
Logging (SLF4J), muhim amallar jurnalga yoziladi (buyurtma yaratildi, status o'zgardi).
Ma'lumotlar bazasi zaxira nusxasi (backup) va tiklash imkoniyati.
Docker va docker-compose, HTTPS, domen.
Qo'shimcha texnik talablar
Migratsiyalar Flyway orqali boshqariladi (ddl-auto=update o'rniga), har o'zgarish
versiyalangan SQL fayl bo'ladi.
Katalog va sozlamalar Caffeine keshida saqlanadi, admin o'zgartirganda kesh
tozalanadi.
Yuklangan rasm avtomatik WebP formatga va bir nechta o'lchamga (kichik, o'rta, asl)
o'tkaziladi, shunda sayt tez ochiladi.
Real vaqt kuzatuvi uchun SSE (Server-Sent Events) ishlatiladi, bu WebSocket'dan
sodda.
